# 蒸馏 Writing Skill

根据全部范文创建一个可复用、与主题无关的 Writing Skill。还原这些文字是
怎样写成的，不要复述它们写了什么、写给谁，或持有什么立场。

## 分析语料

读完所有范文后再起草 Skill。

1. 区分作者正文与引语、提示词、固定模板、元数据、转载片段和平台格式。
   不要把不属于目标作者的文字提炼成风格规则。
2. 区分稳定的风格机制与篇幅、格式、正式程度带来的变化。只把这些变化保留
   为可选的呈现模式，绝不能变成主题限制或受众限制。
3. 在内部建立证据矩阵，覆盖：
   - 声音、叙述距离、叙述视角和情绪温度；
   - 解释、论述、描写和安放例子的形式；
   - 全文结构、开头、展开、转场和结尾；
   - 段落形态、句子节奏、行文速度和信息密度；
   - 用词、语域、反复承担特定功能的表达、标点和格式；
   - 修辞、强调、幽默、不确定性表达和行动号召；
   - 修改标准、风格失败方式，以及这些文字有意避开的语言质感。
4. 横向比较范文，不要逐篇摘要。识别重复规律、有意义的变化、矛盾和
   足够稳定的缺席信号。
5. 语料足够时，测量可观察的倾向。使用诚实的范围和相对频率，不要制造
   虚假的精确数字。

## 判断证据等级

先判断每个候选规律的证据等级，再把它写成规则：

- **不变量**：在适用范文之间反复出现，或在一篇内容充分的范文中持续出现。
  只有当违背它会明显破坏写作方法时，才写成硬约束。
- **默认项**：占主导但并非没有例外。写成通常采用的选择，同时允许有理由
  的偏离。
- **条件项**：与篇幅、格式、正式程度或修辞功能相关。把触发条件和对应写法
  写在一起，但不能限制内容主题。
- **偶然项**：只出现一次、由题材造成或证据不足。排除。

只有当语料覆盖面足够时，才把“没有出现”视为证据。不要默认把未观察到的
写法判定为禁用项。范文之间存在冲突时，把差异保留为选择规则，不要取平均
后变成空泛建议。

## 提炼可执行规则

把证据转化为作者可以执行、编辑可以检查的写作决策。

- 每条规则都写清动作、适用条件和可观察结果。
- 仅对不变量使用“必须”；对主导倾向使用“默认”；对变体使用“当……时”；
  只有得到证据支持的反模式才能使用“避免”。
- 保留技法之间的关系：什么情况触发、它解决什么问题、出现频率如何，以及
  后面通常接什么。
- 提炼文字怎样呈现材料：怎样展开一点、安放例子、控制强调、衔接段落和改变
  信息密度。绝不能规定应该写哪些观点、例子、立场或事实。
- 从规则中排除范文特有的主题、受众、目的、事实、姓名、论断、观点、价值观、
  专业领域、个人细节和标志性措辞。只允许在下文规定的简短证据示例中保留
  原文语言。
- 不要擅自加入通用写作常识、流行的“去 AI 味”禁令、体裁惯例、内容方法论
  或编辑定位，除非它们是描述已观察到的风格机制所必需的。

如果语料中存在多个稳定子类型，先给出共享内核，再写带条件的子类型规则。
不要把互不兼容的声音或文档类型混成一个虚构的平均风格。

## 添加证据示例

深层 Writing Skill 必须可核验。在每段重要的概念性总结或紧密相关的规则组
后面，直接放置简短的证据示例。

- 增加一个“示例”区块，放入一至三个来自作者正文、能够支持该概念的案例。
- 只截取足以呈现所述机制的最短片段。通常一个短语、一句话、相邻两句话，
  或从原文结构提炼的骨架就足够。
- 保留证据中的句法、标点、节奏、分段或修辞动作。姓名、机构、产品、精确
  数字和主题专有名词如果不影响观察风格，就替换为中性占位符。
- 每个片段后用一行说明它证明了什么，只指出可观察的形式特征，不解释原文
  讨论的内容。
- 如果直接摘录会暴露身份信息或使 Skill 过于冗长，就写一个紧贴原文机制的
  去标识化重构，并标注为“证据改写”，不要伪装成原文引语。
- 有多篇范文时，尽量使用来自不同范文的证据。不要用同一句漂亮原文证明多个
  无关概念。
- 把证据当作风格演示，不要当作短语库。生成的 Writing Skill 不得要求复用
  示例中的主题、事实、观点、意象或辨识度过高的措辞。

证据示例可以具体，因为它们负责验证提炼是否成立；写作规则本身仍须与主题
无关，只描述文字的形式。

## 构建输出 Skill

只生成一个自包含的 `SKILL.md`。

前言必须严格为：

```yaml
---
name: <请求的-skill-id>
description: <使用这种风格写作或修改任意主题的内容>
---
```

正文使用最有利于应用 Skill 的语言。保持足够精炼，使其适合在每次写作任务
中加载；同时必须足够具体，能够产生可辨识的写作方法。宁可生成一份带有
精选证据的深层 Skill，也不要只给一组缺乏证据的抽象结论。

按照证据组织正文，不要套用内容模板或体裁模板。但必须让以下决策容易找到：

1. **风格签名**：用与主题无关的语言概括这种文字可辨识的整体质感。
2. **声音与表达**：视角、叙述距离、情绪温度、正式程度和直接程度。
3. **结构与行进**：开头方式、推进、转场、强调、段落节奏、句子节奏和
   结尾方式。
4. **语言与修辞**：用词、句法、标点、格式、解释模式和有证据支持的标志性
   技法。
5. **呈现模式**：根据篇幅、格式、正式程度或修辞功能调整写法，但保持风格
   内核不变。
6. **起草与修改流程**：怎样把风格应用到任意输入，并清除风格漂移。
7. **护栏与终检**：高置信度风格失败模式和简短、可操作的检查清单。

每段高价值的概念性总结后面都要紧跟简短的“示例”区块。证据必须放在它所
支持的概念旁边，不要统一堆到脱离上下文的附录中。

必须明确说明：新文章的主题、事实、立场、例子和受众全部来自用户当前请求。
Skill 只提供写作风格，不得从范文中带入这些内容。

如果范文无法为某个章节或维度提供可靠指导，就省略它。不要用空分类凑结构。

## 返回前验证

在内部审查生成的 Skill：

1. **覆盖度**：每个高置信度规律都有可执行规则。
2. **可追溯性**：每条强规则都能由多篇范文、一篇内容充分的范文中的重复
   证据，或明确的条件模式支持。
3. **证据质量**：每段概念性总结都有相关且最小充分的示例，每个示例都能
   直接呈现它所声称的风格特征。
4. **保真度**：按 Skill 写出的新内容会复现范文的声音、结构、节奏和语言
   质感，但不会复现范文的主题内容。
5. **辨识度**：Skill 说明了这种方法与合格但普通的草稿有何区别。
6. **一致性**：硬规则、默认项、条件项和示例互不冲突。
7. **校准性**：把 Skill 用于一个陌生的中性主题时，仍能产生有辨识度的
   写作决策，同时不会借用范文内容。
8. **可移植性**：成品不包含源文件引用、身份信息、外部依赖、宿主指令或
   生命周期信息，只保留最小且去标识化的证据示例。
9. **可执行性**：另一个 Agent 无需读取原始范文，就能用 Skill 完成写作和
   修改。

修改所有空泛、无证据、无法检查或过度照搬范文的规则。如果素材不包含实质性
作者正文，或无法支持任何可靠的风格规律，应报告证据不足，不要虚构风格。
