# 将 Markdown 来源整合进默认 Wiki

整合一份 Markdown 来源文档时，使用本参考。

执行步骤：

1. 阅读来源 Markdown。
2. 阅读 `wiki-conventions.md`，查看可用的 Wiki 路径，并检查 `SCHEMA.md`、`index.md` 以及可能需要变更的已有页面。
3. 判断来源的主要自然语言、主要主题、具名实体、其他名称、稳定身份或定义、带日期的观察或变化状态，以及有用关系。
4. 搜索已有标题、路径、别名、标签和链接，寻找应当吸收这些证据的规范页面。
5. 第一次整合来源时，先建立 `SCHEMA.md` 和 `index.md`，再添加知识页面。用第一份来源建立第一个有用主题，但不要把它声明为 Wiki 的永久边界。
6. 对有价值的证据分类，在 `topics/`、`entities/` 或 `views/` 下创建或更新聚焦页面。新的无关来源可以创建新的顶层主题，不需要改变已有主题，也不要被强行归入已有主题。
7. 新页面使用来源的主要语言。已有页面沿用已经确立的语言，并将有用的跨语言术语加入别名。
8. 在受影响页面中更新综合结论、出处、矛盾、限制条件、别名、标签、简洁的首段摘要和有意义的相对 Markdown 链接。有证据支持明确关系时，用关系的实际含义命名，不要把所有链接都放进笼统的“相关”章节。
9. 只有当导航确实需要公开新的或发生变化的主题枢纽、重要实体或视图时，才更新 `index.md`。确保其他页面仍可通过有意义的链接被发现。

写作规则：

- 进行整合而不是倾倒内容，让每个来源都增强现有 Wiki 的知识网络。
- 优先创建能够跨来源持续积累的稳定页面。
- 只有当主题、实体或跨主题视图具有持续价值时才创建新页面。某个主题即使只在一份来源中出现，只要它是该来源的核心，也可以独立成页。
- 允许 Wiki 从一份文档逐渐扩展到多个彼此无关的领域。不要把第一份来源的主题、词表或语言当成全局限制。
- 每个对象只保留一个规范页面。使用别名、标签和链接表达译名、同义词及多重主题归属，不要创建重复页面。
- 对证据所描述的对象或概念建模，而不是复刻来源的标题层级或存储形态。不要把来源中的每个章节都转换成页面。
- 将稳定身份和定义与带日期的观察、变化状态、预测及特定来源的论断分开。时效性强的陈述应在附近保留日期和出处。
- 不要创建来源页或文档镜像页；原始文档仍保留在生成 Wiki 之外。
- 新证据确认、细化、反驳或取代旧论断时，更新已有页面。
- 使用稳定的来源标识和必要的简短来源注释明确依据，不要把原始 Markdown 复制进页面。
- 遵循 `wiki-conventions.md` 中的目录与页面规范。
- 保持页面简洁、聚焦、易于导航，不要改写无关页面。
- 不要因为所选 Skill 变化而重新生成整个 Wiki。

完成标准：

- 来源中有价值的内容已被综合进 Wiki。
- 相关页面已经反映新证据。
- 新建和更新的页面使用与其来源相适合且内部连贯的语言。
- 当本次工作初始化或实质改变 Wiki 时，`SCHEMA.md` 和 `index.md` 均存在且保持一致。
